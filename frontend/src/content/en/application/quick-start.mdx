# Quick Start

The authoritative Matrix-Law deployment sources are in `deploy/two-server/`.
Local-candidate mode uses two isolated containers to simulate the capability and
law-firm tenant servers for development and acceptance only. The cloud target is
native processes managed by systemd on two independent Linux hosts; Docker/Compose
is not the production deployment architecture.

## Prerequisites

- Docker Engine and the Docker Compose plugin
- The Matrix-Law repository checked out on the host

## Start the local candidate

Run these commands from the Matrix-Law repository root:

```bash
./scripts/bootstrap.sh
./scripts/doctor.sh
./deploy/two-server/start.sh
```

The first initialization creates local administrator credentials in the
permission-restricted runtime directory. Read them locally and keep them private.
Do not place secrets in shell history, source files, tickets, chat, or logs.

Open one of these local URLs:

- Capability operations: [http://127.0.0.1:4110/console/](http://127.0.0.1:4110/console/)
- Law-firm administration: [http://127.0.0.1:4111/law-admin/](http://127.0.0.1:4111/law-admin/)
- Lawyer sign-in: [http://127.0.0.1:4111/login](http://127.0.0.1:4111/login)

Stop the containers and retain local data:

```bash
./deploy/two-server/stop.sh
```

This is a local candidate environment. It does not establish production security,
real-provider quality, real-material legal quality, billing, or disaster-recovery
readiness.
