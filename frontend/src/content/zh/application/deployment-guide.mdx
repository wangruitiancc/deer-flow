# 部署指南

Matrix-Law 只有一个部署入口：Matrix-Law 仓库中的 `deploy/two-server/`。仓库的
本机模式运行两个容器模拟相互独立的服务器，仅供开发和候选验收；它不是生产安装器。

## 云端目标架构

生产目标是两台独立 Linux 主机上的原生进程和 systemd 服务。能力端管理 Gateway、运营台、模型中转、PostgreSQL 与 Redis；律所端管理律师工作台、律所后台、法律扩展、私有 OCR、PostgreSQL、Redis、对象存储和 Nginx。两端数据库与 Redis 相互隔离。当前原生发布工具仍是原型，目标主机、发行版、生产密钥托管和跨机验收尚未完成。

## 启动和停止本机候选

从仓库根目录运行：

```bash
./scripts/bootstrap.sh
./scripts/doctor.sh
./deploy/two-server/start.sh
```

启动脚本只接受 `TWO_SERVER_DEPLOYMENT_MODE=local-candidate`。首次初始化会在本机私有、
权限受限的目录中创建运行凭据。该目录不得提交到源码管理，也不要公开目录内容。

| 服务 | 本机地址 |
| --- | --- |
| 能力运营后台 | `http://127.0.0.1:4110/console/` |
| 律所管理后台 | `http://127.0.0.1:4111/law-admin/` |
| 律师工作台 | `http://127.0.0.1:4111/login` |

停止服务并保留本机数据：

```bash
./deploy/two-server/stop.sh
```

## 数据和凭据边界

能力端和租户端容器使用独立的 PostgreSQL 数据库、Redis 和服务凭据。平台模型与供应商
凭据属于能力端。法律材料、OCR 结果、引用和律师复核属于租户数据域。租户快照不能包含
供应商密钥或可复用的平台凭据。

本机运行目录包含私钥、证书、密码和生成的环境文件。请限制目录权限，不要提交到源码，
也不要复制到文档、支持包或日志。本机候选使用本地 PKI 和凭据，不能证明生产 KMS、
密钥轮换或恢复流程已经就绪。

## 生产验收

本机启动脚本会拒绝生产模式，不得用于初始化生产账号。生产部署前需要单独建立并留存以下证据：

- 两台独立管理的主机、生产 PKI、密钥托管、轮换和 MFA；
- 每条外部供应商及法律材料处理路径的数据处理、保留、地域和人工复核要求；
- 已签名发布制品、加密异地备份和恢复演练；
- 生产等价负载、监控、告警送达、访问控制和事件处置流程；
- 真实律所工作流与法律质量验收、账务核对、客户支持和退出流程。

本机 HTTP 检查、合成测试和容器健康状态只属于候选环境证据，不能替代上述生产门槛。
